# 语音陪伴与关系计分

普通聊天接入现有关系养成，不直接增加饱食、心情、精力，也不立即增加亲密度。聊天、喂食和抚摸共用十分钟计分间隔，每个连续24小时窗口最多三次；窗口结算沿用计划的 −3 / −1 / 0 / +2。

## 一轮聊天何时算有效

1. 后端实际 ASR 流程产生非空转写。`pet_audio` 来源标记和 `pet_turn` 编号由适配层生成；唤醒词、调试文本、纯显示消息不取得收音来源标记。
2. 设备收到该轮回复开始和非空回复文本。
3. 远端回复音频经过成功解码，并有非空 PCM 交给原音频驱动。音频包只增加本地队列元数据，不改动网络二进制帧格式；本地提示音不增加该统计。
4. 收到回复结束，解码、播放队列及在途任务已排空。语音 epoch 仍匹配，且没有取消、设置页、待确认记忆页或实际睡眠。
5. 同轮没有已成功执行的照顾动作，且仍满足统一计分间隔和窗口上限。

对话完成只消费一次机会。同轮重复转写、重复结束或较长回复不重复计分；即使因为十分钟间隔未得分，也不会把旧完成事件留到之后补领。断电只保留已经计入原有 V3 存档的关系计数，不恢复半途对话。

## 实现和可见状态

- `backend/pet_voice_source.py`：连接限定的 ContextVar 来源；并发连接隔离，异常恢复，不根据用户文字推断来源。
- 固定上游补丁：仅 ASR 调用声明真实收音；实际 STT 序列化函数带来源和正整数轮次编号。旧云端无这些字段时不推断为有效收音。
- `pet_conversation.h`：不保存对话内容的设备端完成追踪。
- `PetState::Chat()`：复用已有 `Interaction()` 规则。
- `self.pet.get_state` / USB 状态增加 `relationship_interactions`、`relationship_window_seconds`、`relationship_spacing_seconds`，便于验证和解释。

## 验证边界

编译期执行三组真实追踪器和 reducer 检查，覆盖正常完成、重复事件、无音频、无回复、非收音输入、取消、同轮照顾、时间间隔和窗口结算。Python 检查覆盖来源隔离、异常清理、真实上游 STT 序列化及 ASR 唯一授权入口；两端补丁在固定原始源码上重放并重复应用。

这些检查不能证明实际麦克风识别质量、扬声器听感或关系速率适合长期使用。驱动输出返回并不等于外部麦克风录到了声音。设备写入、启动和实际收音的证据须分别记录，不用编译或合成事件测试替代实机验收。
