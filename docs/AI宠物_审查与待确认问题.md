# 方案审查与待确认问题

日期：2026-10-30。使用「产品方案指南」组织功能与验收，使用「strategy-red-team」逐项反查关键假设。以下是同一助手的多轮审查，不是独立专家评审或实机测试。

## 1. 审查一：能否做成，而非看起来完整

| 原始设想／疑问 | 审查发现 | 写入计划的修正 |
|---|---|---|
| 芯片相同便能直接复现FUMI？ | 板型、触摸、驱动、分区与工程环境并不相同 | 保留原小智工程；FUMI只参考机制 |
| 所有GIF都能直接铺满？ | 原布局预留状态栏与文本；播放器还需事件和锁管理 | 独立全屏模式，保留驱动，检查资源索引 |
| 最新表情库比现有更好？ | 当前上游已列Otto1.0.2，最新说明不能当旧版接口 | 先验证锁定版本，再决定升级 |
| 16MB足够大，可任意加资源？ | 应用槽约3.94MiB，压缩图大小不等于解码内存 | 分开核对应用槽、资源分区、运行堆与音频 |
| 改个角色提示词就完成AI宠物？ | 无法证明宠物状态真实变化 | 本地reducer作为真值；工具结果驱动AI回应 |

## 2. 审查二：按真实使用过程攻击细节

| 反问 | 会发生的问题 | 修正规则 |
|---|---|---|
| 长按睡眠后松手会不会顺便喂食？ | click与long事件同时触发 | 长按消费本次手势，释放不补短按 |
| 正在说话还能乱按喂食吗？ | 语音与动画争抢、用户不知道动作成功没 | 忙碌时侧键照顾拒绝；中键用于取消 |
| 工具本身处在语音会话中，是否也被BUSY拒绝？ | 语音照顾永远不能成功 | 同会话思考阶段工具允许执行，区别物理输入 |
| 说晚安后立刻断音入睡？ | 对话被截断或永远等TTS | 提交睡眠意图，播完入睡，失败／超时5秒兜底 |
| 静音是否意味着设备不上传声音？ | 形成错误隐私预期 | 明确仅关闭输出，非禁麦；不增加虚构隐私模式 |
| 没有屏幕状态栏怎么调音量？ | 失去原音量键功能 | 长按设置，保留音量与静音入口 |
| 关机一星期会不会回来饿死？ | 不可靠时钟与负担式养成 | 不死亡；未知关机时间冻结，生理补算封顶24小时、关系7窗口 |
| 不停睡醒、重启会不会刷亲密？ | 计时和上限被重置 | 保留计时余数、照顾窗口和存档；共享冷却 |
| 连续断网重试是否重复喂食？ | 工具重复执行 | 本轮去重及全局冷却，返回真实事件序号 |

## 3. Red-team：五个可能使方案失败的假设

优先级=影响×发生可能×低成本验证价值，均按1–5估计；这是排检查顺序，不是统计概率。

| 排序 | 最强支持理由 | Fails if：何时不成立 | 分数 | 最便宜的验证／本周证据 | 停止／改路标准 |
|---|---|---|---:|---|---|
| 1 原版工程可复现 | 板型和版本已识别，有原固件备份 | 上游同标签与卖家固件差异导致屏幕／音频失效 | 5×3×5=75 | 原版构建，逐键映射，与现有语音录音对照 | 原版不能稳定运行就暂停业务改造，先补板型差异 |
| 2 官方后台能调用新工具 | v2.0.4有MCP注册入口 | 工具可列出却无法被当前智能体稳定选用 | 5×3×5=75 | 一个只读状态工具，5条明确查询并查看调用结果 | 半天定位仍无闭环，评估兼容服务端；不宣称AI联动完成 |
| 3 动画不破坏语音 | 分辨率小、PSRAM8MB，已有GIF入口 | 动画造成欠载、看门狗或延迟明显变差 | 5×3×4=60 | 双表情+20轮语音，与关闭动画对照 | 有音频断续或p95恶化>20%，先降帧；仍失败换程序绘制 |
| 4 状态、记忆与播报一致 | 确定性reducer和资料工具可返回真实结果 | 重试重复执行、资料未取用，或模型说成功实际失败 | 5×3×4=60 | 重放调用、断网、冷却、睡眠、新会话记忆取用 | 30条评测的关键事实与动作存在错误，不对外演示「可靠动作」 |
| 5 三键足够自然 | 短按照顾，中键语音，长按低频功能 | 用户分不清喂食与音量，长按误触严重 | 4×3×5=60 | 3位新用户看一张操作卡完成五项任务 | 任一关键任务2/3人失败，优先改映射而非补长说明 |

### 经审查仍成立的部分

- 现有硬件足以成为验证目标：用户已有可用语音设备，避免新增采购。
- 极简大眼睛与当前240×240资源方向匹配；明确许可的候选已找到。
- 全屏、实体照顾、本地离线和云端表达的职责划分清楚，可逐段交付。

### 还不能评估的部分

电池实际容量与老化、卖家对固件的改动、后台当前工具策略、实物按键位置、持续运行功耗、用户是否愿意连续使用。没有这些证据就不写量产、续航或留存结论。
