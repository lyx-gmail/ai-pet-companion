# 设备端记忆管理

目标：设置页查看称呼和四条偏好，显示具体内容后确认删除；更正通过退出设置后重新语音提案完成。电脑数据库是唯一可写资料源。设备不持有记忆服务密钥，不创建可写离线副本。

## 已实现的后端通道

复用语音后端的8003端口：`POST /pet/memory`。同时校验绑定设备、Client-ID和现有签名Bearer令牌；不复用允许无签名访问的例外白名单。不增加公开记忆服务端口，不调用模型。设备最终将复用自身已取得的语音令牌。

| action | 参数 | 行为 |
|---|---|---|
| profile | 无 | 只读已确认资料及revision |
| delete | field、revision | 仅创建30秒删除草稿，返回PENDING；不删除 |
| confirm | id | 提交既有草稿，以固定操作ID支持幂等重试 |
| cancel | id | 取消草稿，不修改已确认资料 |

field仅支持name、preference0至preference3及all。all会删除资料和经历，设备确认页必须写明“全部记忆（含经历）”。入口不接受任意字段写入；更正继续使用既有语音提案和实体确认流程。

旧revision、已过期或不存在的草稿返回明确失败；接口异常不回传原始错误详情。所有响应禁止缓存。网络超时只能标记结果未知，不能显示删除成功；设备需保留同一草稿ID重试或重新读取服务端资料。

## 设备页实现

- 在现有记忆设置页内逐条翻阅五个槽位，并提供全部删除、更正说明及返回。
- 选择删除后先显示字段与具体内容；主键确认、侧键取消，设备最多等待25秒（服务端草稿30秒到期）。导航和查看不发送提交请求。
- 网络请求在独立任务执行，结果通过应用队列回到LVGL线程；使用页面代次丢弃退出后的旧结果。
- 请求失败清除当前资料的有效标记，显示不可用；不得把旧缓存当作当前资料，也不得回写恢复已删内容。
- 已提交但确认响应丢失时，不重建草稿、不使用新操作ID重复写入；查询或重试后才能报告结果。
- 删除完成不自动开麦。下一次语音经过资料版本检查清理旧上下文；活动会话也会检查版本变化并关闭旧连接，设备丢弃旧会话排队音频。

原生HTTP客户端使用本地语音的`pet_ws`凭据，只访问预设的本地地址，禁止重定向，请求超时3秒、响应上限8192字节。资料只在页面打开时保留于RAM，退出后清空；未获回执的提交保留原操作ID，重新进入页面后可重试确认。

确认倒计时使用设备单调时钟，避免上游系统时间的时区偏移导致即时过期。服务端仍以自己的时间校验草稿；页面倒计时不是绕过服务端有效期的授权。

设备代码已编译，菜单状态机的三组编译期检查通过；以下实机HTTP联调已通过，尚不代表视觉与实体开关触点验收。

## 活动会话和旧音频取消（2026-11-01）

本地Provider在取得首轮有效记忆快照后，每500ms检查一次资料版本。变化或读取失效时取消旧轮次、清空待发送内容及个人对话上下文，关闭连接；自身提案查询期间暂停检查，晚到的检查结果不能覆盖新快照。关闭连接时回收检查任务。设备通道关闭时阻止旧回调、更新会话代次并清空解码和播放队列。已交给硬件的当前音频片段不能由此撤回，不能宣称零延迟停止。

`evaluation/voice-memory-cancel-flow-check.json`使用真实独立RAM记忆、固定上游ConnectionHandler、TTS队列和回环WebSocket，验证更正和删除无须新用户轮次即可关闭旧连接、清空队列及上下文。16项客户端和版本检查通过，含晚到结果、自身查询及失败任务回收。

当前设备固件SHA-256为`8aee09930300d01f146ee09451c7a962f108206c301ea6b837b67e02665dd89d`。`evaluation/device-audio-cancel-check.json`经真实设备、静音Opus和隔离记忆删除验证：丢弃7个解码包、2个播放任务，剩余队列为0，返回idle。正式记忆未改动，未调用模型。关闭握手可比设备停止排队播放更晚结束，测试按WebSocket默认握手超时独立等待；这不是声学验收。新图像启动和记忆查看回归通过；上文完整菜单删除测试来自上一固件。
