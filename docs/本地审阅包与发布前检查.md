# 本地审阅包与发布前检查

本地源码审阅包用于检查交付内容。项目自有代码采用 GPL-3.0-or-later；v0.1作为源码预览版交付。`release_ready=false`表示完整产品验收尚未完成，不代表源码预览版不可发布。

## 生成

Python标准库即可运行，不调用模型，也不访问设备串口：

```powershell
python scripts/test_review_bundle.py
python scripts/prepare-review-bundle.py
python scripts/prepare-review-bundle.py --bundle
```

输出位于本机忽略目录 `.runtime/release/ai-pet-review.zip`。公开目录的 `evaluation/release-preflight.json` 是当前源码审阅清单；包内 `REVIEW_MANIFEST.json` 冻结该次打包的相对路径、大小、SHA-256及未通过的发布条件。观察或评测记录更新后，应重新生成审阅包。

## 实际检查

- 只从显式源码目录与少量根文件收集；`.env`、数据库、Flash备份、私有日志、SDK、构建产物不进入包。允许的 `.env.example` 仅提供配置占位。
- 拒绝目录链接和越过工作区的文件；打包前后比对源码哈希，遇到变化不替换此前的审阅包。
- 比较本地私有配置中的长凭据，并检查常见密钥、URL令牌和私钥格式；结果只保留文件位置与类别，不输出匹配值。文件名携带匹配凭据同样阻止打包并脱敏报告。
- 使用项目内的临时文件完成ZIP，再替换最终文件；失败时清理自己的未完成文件，不使用系统TEMP存放源码或依赖。
- 五项隔离测试覆盖私有目录排除、凭据泄漏阻止、文件名脱敏、源码在检查后变化时保留旧包，以及归档内链接缺失时阻止交付。

每次生成时逐项复核ZIP成员哈希，并检查归档内Markdown本地链接；缺失目标会阻止替换旧包。校验摘要保存在本机 `.runtime/release/bundle-verification.json`。该结果是源码快照的有限检查，不替代人工内容审阅或从零安装验证。

独立解压目录中已通过打包边界、USB回执解析、启动日志解析三组Python检查，见[解压检查范围](../evaluation/review-bundle-smoke.json)。固件依赖锁定文件包含在归档中。这不是完整后端安装或重新编译成功的证明。
