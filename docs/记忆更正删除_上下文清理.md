# 记忆更正/删除后的语音上下文清理

2026-10-31。电脑端记忆服务原本能更正、删除投影，但语音服务的历史 user、assistant、tool 消息可能保留旧资料。仅把最新资料放进 system 并不能清除这些旧消息。

现在语音记忆客户端读取带资料版本号的召回快照。每个语音连接独立持有记忆适配器、确认状态和已观察版本；不再复用服务器原型的连接状态。版本变化时，在下一轮生成前移除旧聊天/工具历史与 TTS 文本缓存，仅保留系统提示和当前这句用户输入。版本不变则保留正常上下文。记忆服务不可用时同样清理旧历史，并明确报告无法读取，不能依赖旧称呼继续猜测。

迟到的旧召回不会清理新一轮消息；旧轮次在召回结束、流式循环、工具结果返回和历史提交前增加代次检查。普通“我叫什么”查询也不再进入称呼保存意图分支。

验证包括：

- 9项 HTTP 客户端与真实上游对话渲染器回归：版本校验、更正、删除、服务故障、正常历史保留、迟到召回及连接隔离。
- 5项记忆确认边界回归：保留确认/取消/错误编号/超时与保存结果未知的规则。
- 固定上游补丁首次与重复应用检查、Python 语法检查。
- 独立真实 Node 内存数据库→认证 HTTP→实际记忆 Provider→固定上游 Dialogue 渲染器闭环。更正/删除后检查模型将收到的完整消息，确认旧称呼不在其中；服务断开后也清除旧资料。见 `evaluation/voice-memory-context-check.json`。

闭环没有调用模型，没有修改正式记忆库，也不是实体语音或并发音频验收。已经听到或已排入设备播放链路的音频不在这次验证范围；尚需验证删除与正在播放回复之间的即时取消。资料管理界面、有效聊天计入关系及其余交付仍需继续完成。
