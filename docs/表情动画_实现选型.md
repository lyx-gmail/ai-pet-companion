# 表情动画实现选型与视觉验收

更新：2026-10-30。用户补充要求：优先寻找成熟实现，尽可能灵动；不接受临时画几种生硬的眼形作为成品。

## 决策

日常主脸优先做 **RoboEyes 实时运动内核 + 现有 LVGL 屏幕驱动适配** 的技术验证，先保留其原有眨眼、随机视线和连续形变逻辑。眼形和动作节奏用现有可视化工具调试。Otto GIF保留为对照及快速兼容方案，不因接入容易就自动当最终视觉效果。

这是针对当前设备、代码基础和展示目标的选择，不是已完成实机性能比较后的结论。最终采用须通过下述同机测试。现阶段没有自行重写一套眼睛运动算法，也没有刷入新界面。

## 怎样做出灵动感

- **待机也有细微生命感**：沿用成熟引擎的随机眨眼、视线停留与过渡，避免每几秒完整重复同一个GIF。降低看向频率和幅度，不让眼睛不停抖动。
- **状态改变是连续动作**：开心、困倦、疑惑从当前姿态过渡；动作结束回到当下基础状态。不能把每次情绪切换都处理为黑屏再换图。
- **即时反馈与完整动作分开**：按键后先给可见响应，再播放完整喂食或开心动作；用户进入聆听时及时中断非关键动作。沿用计划书的语音/动作/底层状态优先级。
- **画面统一**：同一双眼、同一颜色和线条语言。喂食、喜欢、困倦允许小型辅助动效，但不混用圆环、椭圆、像素脸和卡通贴图。没有现成同风格素材时，先用编辑器设计并审查动作分镜。
- **声音不能只是字幕替身**：听、想、说通过眼形及节奏区分；日常仍不显示状态栏或聊天字幕。不把每次喂食都变成长篇播报。

## 实现顺序和验证门槛

1. 固定上游版本和原许可证；已有驱动继续独占SPI，动画只使用现有LVGL绘制通道。先解决旧固件清单中已下架的无关动画依赖，不以升级所有依赖绕开问题。
2. 只接一个实时内核，先跑待机/开心/困倦/疑惑四种主脸；保持原语音收放音。调试设置及配网作为独立模式，不被全屏脸盖住。
3. 在设备分辨率下做连续预览，保存参数；用户不必反复决定所有细节，我先按自然、克制、可辨识的标准调好。
4. 实机对照GIF与实时绘制：记录帧间隔分布、最长卡顿、内存、语音播放时的动画变化及音频中断情况。25–30fps是起始目标，不是当前实测数值；不为追50/60fps损害语音。
5. 再加入喂食/抚摸/睡眠动作，验证任意阶段切换、连续按键、语音打断、故障页与恢复；录制原速长镜头，不能靠剪辑掩盖跳变。

验收：240×240等比画布、日常无栏无字；待机至少看30秒不觉机械重复；表情切换无黑闪和明显跳脸；按键可见响应目标150ms内；语音期间仍连贯；连续运行10分钟无持续内存增长。具体测量结果另存证据，不预填通过。

## 当前适配结果（2026-10-30）

RoboEyes实时内核已通过LVGL绘制适配进入目标板固件，完整编译链接通过；加入按键、存档和只读工具后应用2,724,768字节，小于4,128,768字节应用分区，余量约34%。证据见`evaluation/firmware-build.json`。尚未刷写，因此不声称实机流畅、音频兼容或视觉验收通过。

保留上游动作算法，只修复一处默认眼间距在坐标初始化后才声明的问题；不通过关闭编译警告掩盖未初始化读取。LVGL绘制直接使用矢量图元，33ms定时更新，未新增整屏双缓冲。设置页与三键入口已接线；切换后的流畅度、语音并行表现仍待实机验证。

### 后续动作编排标准（设计目标，尚未完成接线）

| 场景 | 动作顺序 | 节制与打断 |
| --- | --- | --- |
| 待机 | 不等间隔眨眼、偶尔看向左右，再回中 | 避免持续摇摆；连续观察30秒检查机械重复 |
| 聆听 | 从当前位置转向中央，保留轻微眨眼和好奇眼形 | 优先打断照顾动作，不能黑屏换脸 |
| 思考 | 克制侧视、短暂停顿，返回中央 | 沿用现有内核，不伪装真实处理进度 |
| 说话 | 中央视线配合情绪眼形、偶尔笑或眨眼 | 首版没有口型；不虚称与音素同步 |
| 喂食 | 先注视，再满足眯眼，短暂停留后回基础状态 | 饱腹或冷却时用轻微拒绝反馈；不重复播完整庆祝 |
| 抚摸 | 柔和开心眼、短促笑意，再恢复 | 与喂食节奏不同；不每次都语音播报 |
| 睡眠 | 逐步下垂再闭眼，唤醒先睁眼再回视线 | 不能仅换一张静态困倦图；睡眠是否息屏由省电策略控制 |
| 断网 | 短暂疑惑后恢复可离线互动的基础脸 | 不持续全屏报错；故障详情在显式诊断页显示 |

辅助食物、爱心或梦泡等画面仅在同风格素材经过预览后加入；不直接混入另一套角色。第一轮实机先验证主脸，再依据观察决定是否需要这些元素。动作调度应按“系统故障/设置、聆听、短交互反馈、情绪基础态、待机”排序，恢复时读取当前状态而非强制回中性脸。
