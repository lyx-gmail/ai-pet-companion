# GitHub 展示与复现方案

日期：2026-10-30｜展示设计稿；v0.1先发布源码预览，实物照片和视频仍待补充。

## 1. 访问者先看到什么

主要读者是招聘方和面试官，通常接触不到实物。首页第一屏必须回答：做了什么、设备实际如何表现、AI记忆有什么证据、哪些是本人新增。阅读详细代码不是理解产品的前提。

建议一句话：**一只会记住你的AI实体伙伴：全屏表情、三键照顾、随互动变化的关系，以及可追溯的长期记忆。**

这句话只有完成对应验收后才可当成已实现描述。开发中的首页逐项标注「已验证／开发中／计划」，不提前使用完成时。

## 2. README顺序

| 位置 | 内容 | 读者得到什么 |
|---|---|---|
| 首屏 | 实物照片、一句话、15–30秒实际设备GIF | 无需安装即可看到全屏表情与按键反应 |
| 第二屏 | 90–120秒实机视频缩略图与可打开链接 | 看完整操作与AI对话 |
| 第三屏 | 三个可核查能力及对应证据入口 | 记得你／真实照顾／关系变化 |
| 第四屏 | 一张架构图与本人新增清单 | 看懂设备、语音后端、记忆服务如何连接 |
| 第五屏 | 评测摘要、已知限制、失败示例 | 判断实际效果与边界 |
| 第六屏 | 最短复现步骤、许可与详细文档 | 进一步运行或审查 |

GIF只展示实机，不将网页模拟器画面冒充硬件。视频链接要在发布后用未登录窗口核对可访问性；不预设任意嵌入方式一定在GitHub内播放，准备缩略图和文件链接退路。

## 3. 拍摄脚本与证据

| 片段 | 内容 | 证据要求 |
|---|---|---|
| A 15–30秒 | 手指按喂食／抚摸，屏幕全屏变化 | 镜头同时看到实体按键和屏幕，不能仅放资源GIF |
| B 记忆形成 | 告诉宠物「叫我小林，我喜欢天文」，确认保存 | 用虚构资料，展示提案与确认结果 |
| C 跨会话召回 | 结束旧会话／重启后再问称呼与喜好 | 展示会话边界；附profile或recall的脱敏回执 |
| D 状态联动 | 喂食后问「刚才吃过了吗」，再试冷却中的喂食 | 视频回答对应真实revision／结果码 |
| E 遗忘实验 | 独立测试库用虚拟时钟模拟旧经历降权、重提强化 | 清楚标「模拟时间」；不要伪称持续运行30天 |
| F 异常 | 断网仍能按键养成，记忆后端断开不假报保存成功 | 保留一个失败与恢复过程，说明离线边界 |

主视频优先B/C/D，A用于首页动图；睡眠、离线、关系变化与虚拟时间实验作为补充。必要剪辑可加字幕，但不能把不同轮次的状态与回答拼成假的连续成功。

## 4. 建议仓库结构

代码、评测与文档目录已在本地建立；以下结构仍包含待补的实机展示素材。当前交付为源码预览版，实物展示素材继续补充。

```text
README.md                 # 产品入口与演示
firmware/                 # 板型适配、全屏UI、按键、宠物状态
backend/                  # 语音桥接、记忆适配；不复制无关整仓
docs/                     # PRD、架构、取舍、复现、已知问题
demo/                     # 真实照片、压缩GIF、视频缩略图
evaluation/               # 虚构测试集、结果摘要、脱敏调用证据
THIRD_PARTY_NOTICES.md    # 实际采用的上游、版本、许可、修改范围
.env.example             # 仅占位符
```

Flash备份、Wi-Fi配置、账号绑定、密钥、真实聊天数据库和原始音频不进入仓库。演示数据统一使用虚构身份，不依赖发布后再删敏感提交。

## 5. 两层复现

**无硬件审阅路径**：阅读首页→播放视频→运行虚构资料的文本记忆测试→查看输入、证据、召回和删除结果。后端如需API额度，应在运行前写明，另提供已生成的脱敏结果；已有结果查看不需要读者提供Key。尚未实现的离线回放不能写成已提供。

**有同型号硬件复现路径**：核对板型／引脚／分区→备份→按锁定依赖构建→检查产物尺寸→明确写入区域→配置电脑后端→执行标准验收。其他ESP32-S3设备不能仅因芯片同型号便照刷。

第一版不另做精美网页或3D展示站。记忆星图本身可截取真实界面辅助解释；只有GitHub内容不足以说明交互时，再考虑只读回放页面。

## 6. 作品集叙事

先说具体问题：现成语音玩具会聊天，但实体照顾、真实状态和跨会话记忆未必形成同一个闭环。再展示自己的决策与实测，而非把「接入了大模型」当全部成果。

本人新增需要逐项对应代码／记录：全屏显示适配、按键与状态机、关系频率规则、记忆确认与管理、语音工具和记忆服务桥接、异常处理、评测。上游小智提供的基础语音、开源表情库、记忆框架必须单列归属。

结果只写实际测到的数字，如关键用例通过数、按键响应p95、跨会话记忆测试结果和一次修复前后对比；3人试用不能写成市场验证或留存增长。实物无法现场展示不妨碍做项目，但视频和调用证据需要让描述可以核查。

## 7. 发布前检查

- 从未登录窗口打开仓库、文档、图片和视频链接。
- 每项「已实现」都有对应代码、实机证据或测试结果；计划功能标注清楚。
- 复用上游版本与许可齐全；名称不暗示自行研发了整套语音／记忆引擎。
- 数据、密钥与备份未入仓；演示用虚构资料。
- README的运行要求与实际锁定版本一致；电脑关机后的限制写明。

本计划交付不创建远程仓库、不替用户发布；后续完成具体可审阅内容后再执行用户授权的发布动作。
