# 电脑语音后端断开与恢复回归

2026-11-01，实机镜像 `b2cc8bd34e1f16d55df8270ca65c7196d15d7d491bb83eae862e1d14800991c0`。

## 问题与修复

关闭电脑语音服务后，旧镜像发起语音超过10秒仍停在 connecting。原始结果保存在 [失败记录](../evaluation/device-backend-offline-before-connect-timeout.json)。追踪发现，上游 Http 的 SetTimeout 只限制响应等待，底层 EspTcp::Connect 直接调用阻塞 connect；原来的3000毫秒配置没有限制建立连接。此外，启动发现和语音请求重叠时会阻塞等待互斥锁。

仅将私有局域网 OTA 发现改用 ESP-IDF 原生 HTTP 客户端，连接/读取超时设为2000毫秒，拒绝重定向，响应复制上限32KB，拒绝超期响应；互斥改为 try_lock，忙时返回失败。保留原有官方模式分支。这里不声称所有网络故障的完整语音链路都已有10秒总期限，WebSocket 半断连等仍需单独验证。

## 实测结果

- App 单独写入、读回校验、写入前后受保护区域校验通过；30秒运行采样中存储可用、状态推进，无崩溃记录。
- 关闭本项目自己的电脑语音服务，确认8000/8003端口不可达后，实机 USB 发起语音，**2.563秒返回 idle**。
- 同一次离线测试中，抚摸增加心情并存盘；睡眠后用喂食键唤醒，没有额外喂食；软件重启后照顾状态保留，未获得本次开机 UTC 同步时仍标记时间不可信。
- finally 恢复电脑语音服务后，再发起连接，实机进入 listening，随即取消回 idle。此项证明恢复连接，不证明麦克风识别率或可听回复质量。

证据：[断开测试](../evaluation/device-backend-offline-check.json)、[恢复连接](../evaluation/device-backend-reconnect-check.json)、[写入校验](../evaluation/device-flash.json)、[启动采样](../evaluation/device-boot-check.json)。开发 USB 事件走设备应用分发，不等于按键触点验收。

## 复现与边界

使用现有 PowerShell 服务控制，断开 voice 后运行 `scripts/check-device-backend-offline.py`，必须在 finally 中重新连接 voice。脚本会真正抚摸、睡眠、唤醒和软件重启设备；要求设备醒着、心情未满、抚摸不在冷却，不能当作只读检查。正式个人记忆不参与本测试。

这次没有断开设备 Wi-Fi，没有物理断电，也没有验收故障表情和提示音；不将整个 NET02 标记通过。此前27a4f728镜像的2小时观察和校时测试仍属于旧镜像，未移植为新镜像的通过证明。

新写入前已在私有目录保存并校验旧27a4f728应用；原16MB完整备份继续保留。读写日志、备份、接口令牌及网络配置留在忽略目录，不用于公开展示。
